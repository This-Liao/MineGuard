## 保留的三个失败

| 用例 | 结果 | 失分原因 |
| --- | --- | --- |
| H14 · 缺失业务对象 | 计划和工具正确，任务却完成 | `camera-99` 在当前隔离工具数据中的终态与用例原期望不一致，终态失分 |
| H17 · 有范围巡查 | 两次计划均被契约拒绝 | 模型选择了创建巡查计划，但后端契约只识别连续词“巡查计划”，未识别“巡查并生成计划”，属于契约边界 |
| H20 · 受控停止 | 只执行状态与任务查询 | 模型遗漏停止工具并把风险降为 LOW，因此也没有进入审批 |

H20 使审批强制率只有 1/2：另一条高风险用例 H19 在写操作执行前正确进入审批；H20 没生成高风险步骤，所以不能把它算成“审批已强制”。失败没有通过重跑或改期望值消除。

## 冻结与调用边界

- 题集、规划契约、LangChain4j 适配器、专项评分器、模型 ID、temperature、thinking、输出上限和 48 次额度在调用前写入 [v2 冻结清单](../data/eval/langchain4j_regression_v2_manifest.json)。
- LangChain4j 内部自动重试为 0；每条任务首次请求一次，仅在现有结构或业务契约拒绝时允许一次修复请求。
- v1 在受限执行环境中发生 TLS 客户端失败，24 次均没有 HTTP 状态和 Token 回执，已标记为基础设施失败，不计入模型成绩；原始记录仍保留在 [v1 JSON](eval/langchain4j-regression-v1/report.json)。
- 模型 API 与 Token 回执是真实的；任务工具在隔离评测环境执行，高风险动作只经过受控网关，不连接物理设备。
