# 自然语言任务汇报与引用溯源

## 页面怎么用

在任务历史中重新打开已完成任务，结果区会展示“本次发现”“已执行事项”“处置参考”（仅显示有内容的分区）。不必重新提交任务。

- 数量、类别、占比和状态整理成中文句子，不再默认展示 Java 对象字符串。
- 点击句末的 `[1]`、`[2]` 等编号，即可查看这句话对应的来源。
- 数据回执展示工具名称、执行时间、查询条件和原始结果；知识依据展示文档标题、`documentId`、`chunkId`、检索相关度和本任务保存的完整原文。
- 底部“引用来源”也可以打开来源详情。工具调用记录仍然保留，方便核对。

例如，查询回执确实包含 20 条事件，其中人员滞留 5 条时，汇报会写成：

> 3号采区（本次查询时间段）共查询到 20 条安全事件。[1]
>
> 出现次数最多的是人员滞留（5 条，占 25.0%）。频次仅反映本次查询分布，不等同于风险等级或事故原因。[2]

这里 `[1]` 指向事件明细回执，`[2]` 指向聚合统计回执。处置参考另用自己的引用编号，对应实际检索到的知识片段，不与统计来源混用。

## 生成方式与边界

`AgentReportComposer` 使用已有工具结构化结果进行确定性中文整理，知识参考采用原文句子摘录。此步骤不调用 DeepSeek、不重新检索、不执行工业操作，所以不会增加模型请求或 Token 消耗。当前不是另外调用模型进行自由文本总结。

事实陈述与出处分离保存于 `AgentResult.report`：

- `summary`：汇报开头。
- `sections[].statements[]`：中文陈述与对应 `citationIds`。
- `citations[]`：工具回执索引，或知识文档及原文快照。
- `notes`：数据完整性、检索适用性等提示。

引用编号由后端生成，不能由模型编造。前端把检索文本作为纯文本显示，不执行片段中的 HTML 或脚本。检索相关度不是答案置信度；资料包含合成演示内容时保留提示，原文中的演示声明也完整保留。

数据缺失时不编造数量；分类数量与总数不一致时不生成百分比。明细截断时，高等级/处置状态统计只针对返回的样本。零条结果不等于现场不存在风险。巡查计划草案不等于已经派发或完成现场巡查；启动/停止成功回执与独立状态核验分别表述。

## 持久化与历史兼容

新任务在完成时把汇报与 `FINAL_RESULT` 一起保存进原有数据库任务快照和 SSE 历史，无需新增数据库表。

旧任务缺少 `report` 字段时，前端调用 `GET /api/agent/tasks/{id}/report`，后端先校验原任务访问权限，再从该任务已保存的工具回执与证据生成展示。不会修改历史快照、事件序号、计划或审批。任务尚无结果时返回 409。跨租户读取返回 404，未认证返回 401。

如果汇报接口暂时不可用，页面仍保留原任务结果，可展开查看历史原始结果；认证失效不会被兼容逻辑吞掉。重新打开任务即可重试只读转换。
