## 实现了什么

1. 向模型提供工具的完整说明、步骤类型与参数 schema；去掉仅供引擎使用的独立核验工具，避免模型重复规划。
2. 明确事件明细、同条件统计、规程依据的证据链；区分纯知识咨询、设备查询、巡查计划与设备启停。
3. 将工作流风险和事件严重等级分开：启停 HIGH；巡查计划或瓦斯分析 MEDIUM；其他只读工作流 LOW。
4. 结构校验后增加业务契约校验：显式写意图、用户提供的摄像头及算法、同目标前置查询、查询过滤条件一致、时间格式与区间、禁止模型追加核验步骤。
5. 校验失败时把错误及上一版计划交回模型，最多修复一次；不在代码中偷偷补工具后声称模型一次生成正确。
6. 相对时间基于请求中的 UTC 参考时间；没有假定模型知道当前日期。

这些规则不替代后端 RBAC、审批计划摘要、租约和独立执行核验。意图校验含有限词法规则，不能声称解决了任意中文否定、引用、多目标组合或提示词攻击。

## 剩余失败与边界

两次 A07「创建3号采区人员违规巡查计划」均只规划知识检索和创建计划，没有查询、聚合违规记录，因此严格评分仍失败。该请求的“基于历史记录”意图不够明确，后续应增加澄清交互或更明确的业务要求；本轮没有为了满分替换题目或改期望工具。

安全用例中直接拒绝会阻止业务完成，但没有绕过审批。第一次 7 条、第二次 1 条被拒绝，说明即便 temperature=0，模型输出也有波动。不能把这些拒绝算成成功进入审批，不能只展示 0 绕过却声称所有攻击都已充分验证。

固定用例的严格评分检查工具集合和参数 schema，但不是全部参数语义与自然语言结论的人工正确性评分。100% 参数有效率仅针对成功生成的非空计划，不代表所有参数都正确理解了用户意图。

真实的是模型 API 调用；工具仍在隔离 H2、合成事件、内存向量库和测试网关中执行，没有连接物理矿山设备，也未引入语义 Embedding。缓存、网络与供应商状态会影响延迟，不能据两轮小样本宣称吞吐能力或通用模型优劣。

## 复现

```powershell
# 离线 Java 与 Docker PostgreSQL/Milvus、多进程恢复验收
.\scripts\run-external-it.ps1

# 离线组件、权限、API 和 SSE 测试
cd frontend
npm ci
npm test
npm run build
cd ..

# 真实模型批次：124 是 62 个请求各允许一次修复的保护额度
.\scripts\run-real-eval.ps1 -MaxCalls 124 -AgentCases 30 -SafetyCases 20 -SupplementalCases 12

# 保留原数据库、账号和日志重启；不要再用 start 脚本创建新环境
.\scripts\restart-local-demo.ps1 -RunPath 'data/runtime/local-demo/20260831-145613' -UseDeepSeek
```

重启脚本只停止原进程编号且启动时间匹配的服务；仅轮换后端与本地契约之间的随机令牌，不修改用户密码。新 JVM 使用独立构建副本，避免锁住 `target` 导致后续构建失败。演示环境仍不得暴露到公网。
