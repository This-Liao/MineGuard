# Planning v2 留出评测协议

本轮固定使用 `mineguard-planning-v2`，冻结后才新增 24 条 `agent_holdout_v1.json`。此前 30 条原题与 12 条补充题不计入留出集。

## 冻结范围与运行约束

`data/eval/holdout_v1_manifest.json` 保存规划契约、模型请求构造、校验器、评分器、工具实现及本批用例的 SHA-256。文本统一 LF 后计算摘要，避免 Windows / Linux 换行差异。

运行前必须校验全部摘要及新旧 query 不重复。只跑一轮，最多 48 次 DeepSeek 请求（24 个计划各允许至多一次既有修复），temperature=0、thinking=disabled、max_tokens=2048，与 Planning v2 归档一致。模型 API 为真实调用，数据、工业网关、审批身份与数据库使用专门的隔离评测环境。

运行后保留原始成功和失败、调用数、Token 回执及全部用例分母。不根据结果改 prompt、工具期望或风险标签后再重复本批；若要优化，必须建立新版规划器与全新评测批次。本轮继续使用哈希检索隔离环境，不把同时开发的语义检索混入 Agent 版本对比。

## “留出”不等于“第三方盲测”

这些题是在冻结后新增、没有参与 v2 调优的前瞻留出集，覆盖日期、否定、多类型只读、知识咨询、设备状态、计划、受控操作和越界请求。出题者能看见题目与已有业务能力，因此明确标记为开发者可见，不声称外部独立盲测，也无法排除模型预训练数据污染。

24 条题属于小规模领域评测，不代表整个自然语言任务分布。严格评分沿用原评分器，检查工具集合、工作流风险、终态与审批约束；不声称完整验证每个参数的语义、报告可读性或现场安全性。
