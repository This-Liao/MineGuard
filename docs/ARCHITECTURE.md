# MineGuard 架构设计

## 信任边界

浏览器通过认证 REST/SSE 访问 Spring Boot；LLM 只能产生候选计划。后端负责角色、租户、任务归属、计划结构、工具权限、审批、幂等和验证。模型客户端不能直接操作工业网关，也不能提供有效的审批身份。

```text
登录身份 → 任务访问策略 → 持久化任务 / 审批
                             ↓
工作节点 → 数据库租约 / fencing / 版本检查 → 检查点 + 顺序事件
                             ↓
结构化规划 → Tool Registry → 工业 HTTP 接收端
                             ↓
                      独立状态验证 → 终态
数据库事件 → 带认证的 SSE → Vue 时间线
```

## 数据模型与事务

Flyway 的 `V1__durable_workflow_security.sql` 创建：

| 表 | 责任 |
| --- | --- |
| agent_task | 租户/发起人、请求幂等键、状态、快照、版本、事件序号、租约、fence |
| task_event | (task_id, sequence) 唯一的可重放业务事件 |
| task_step | 步骤参数摘要、操作键、STARTED/COMPLETED、结果 |
| task_decision | 审批人、幂等键、请求摘要、决定 |
| app_user / auth_session | BCrypt 密码、角色；随机会话的 SHA-256 摘要与到期时间 |
| auth_throttle / security_audit | 登录失败锁定；登录、用户管理审计记录 |

任务快照更新、相关步骤状态与事件追加放在同一数据库事务中。事务提交后 SSE 才能读取；文件 Trace 是投影，不是恢复的权威状态。无需额外消息队列也能用数据库轮询完成本轮的双实例调度。

创建幂等键按租户、发起人隔离；审批幂等键按任务、审批人隔离。同键异参拒绝，同键同参返回已有任务。并发审批使用行锁，状态、决定、入队与事件一次提交。

## 租约与恢复

核心引擎已按职责拆分，依赖单向，不引入新线程框架或事件总线：

| 组件 | 责任 |
| --- | --- |
| `AgentWorkflowEngine` | 任务应用入口、状态流转、强制执行后验证与最终报告 |
| `WorkflowScheduler` | 容量控制、租约领取、心跳与停机；委托引擎执行 |
| `StepExecutor` | 步骤幂等、工具调用、证据收集、原子检查点 |
| `ApprovalGuard` | 写前复核审批摘要、有效期和审批人的实时权限 |
| `RecoveryCoordinator` | 核验原操作键回执，补记结果；没有回执则禁止重放 |

持久化事务边界仍由 `JdbcAgentTaskStore` 负责。此次拆分不改变计划契约、工具语义或历史评测期望。

认领 SQL 只更新可执行状态且租约空缺/过期的任务，成功时递增 fence。续约、检查点和释放都检查拥有者与 fence；检查点额外检查快照版本与租约未过期。时间采用数据库时钟，避免应用时钟偏差。过期旧节点无法覆盖接管者的状态。

```text
CREATED → PLANNING → RETRIEVING → ANALYZING
                                  ├→ COMPLETED
                                  └→ WAITING_APPROVAL
                                        ├→ COMPLETED（拒绝，无工业写入）
                                        └→ EXECUTING → VERIFYING → COMPLETED
非终态 → FAILED 或 RECOVERY_REQUIRED
```

- WAITING_APPROVAL 不被调度；用户、计划、证据与事件持久保存。
- 已成功检查点的步骤不重复执行；已记录失败的步骤不会在恢复时被误当成功。
- 只读步骤可在崩溃后重试；创建巡查计划目前只是返回草案，不创建外部工单。
- 高风险 STARTED 但缺少完整检查点：查询接收端原操作键的不可变回执。目标与状态一致才补记成功，再执行独立验证。
- 没有回执、回执不一致、查询不可用或写请求结果未知：进入 RECOVERY_REQUIRED，禁止自动重放。

数据库 fencing 只能约束本地提交，不能撤销已经发给设备的请求。因此不声称跨数据库与真实设备的 exactly-once。没有设备侧去重/回执的系统必须保持保守人工核验；迟到请求与网络分区尚需真实网关专项验收。

## 认证与 RBAC

采用 BCrypt cost=12；密码至少 12 字符、UTF-8 不超过 72 字节。会话随机 256 位，数据库仅保存摘要；每次请求重新检查到期时间、禁用状态与角色。连续五次登录失败锁定账号标识五分钟。此机制不是完善的公网防滥用方案，还需网关级全局/IP 限流及监控。

| 角色 | 授权 |
| --- | --- |
| OPERATOR | 发起任务，读取自己的任务 |
| OBSERVER | 读取同租户任务 |
| APPROVER | 读取同租户任务，批准/拒绝其他人的任务 |
| ADMIN | 管理同租户账号、查看任务；不会自动获得发起或审批权限 |

一个账号可具有多个角色，但始终禁止自审批。跨租户/不可见任务返回 404。审批绑定完整计划的规范化 SHA-256 摘要，默认有效 600 秒；执行前检查摘要、期限和审批人仍启用且具有权限。管理员身份或自然语言“已批准”不能绕过这些检查。

HTTP 只接受 Authorization Bearer，不用 Cookie 认证，因此关闭 CSRF；CORS 仅允许本机前端。凭据不放 URL/浏览器持久存储，注销撤销会话。正式部署仍须 TLS、密码生命周期、身份治理和独立安全审查。

## SSE 与 Trace

每个任务具有数据库单调序号；Last-Event-ID 从下一条开始，历史按身份过滤，不依赖订阅实例。终态且最后序号已发送才关闭连接，避免提交竞争丢失最后一批事件。连接期间复核会话，有撤销/禁用即关闭。

Vue 用 fetch 携带 Bearer 请求头解析 SSE，按序号去重并重连。客户端收到事件后读取任务快照，后端始终是状态权威。刷新页面需重新登录，可从任务历史回放全部事件。

TraceRecorder 可从数据库事件重建跨节点 Trace；文件使用原子替换并过滤敏感字段。不记录隐藏思维链。现有审计与 Trace 尚不具备防篡改签名、归档和保留策略。

## 工具与工业契约

PlanValidator 检查 1–10 个步骤、安全且唯一的步骤 ID、参数规范和风险等级；同一目标在一份计划内只能有一次写操作。规划最多修复一次。Registry 再次检查 HIGH_RISK 审批标记。模型自行添加的验证步骤不能替代引擎强制生成的独立验证。

HttpIndustrialGateway 使用 PDF 中 /startTask、/stopTask、/check 的 HTTP 结构，额外要求接收端提供 /contract/* 查询与持久化幂等回执。服务地址只允许 HTTPS 或本机 HTTP，不跟随重定向，有超时、写目标白名单与适配器密钥。失败不自动重试。

IndustrialContractServer 是可独立运行的本地契约服务，采用 H2 保存目标状态和不可变操作回执。同键同参直接返回原回执，同键异参拒绝；状态变更和回执在同一事务内。它是验收替身，不是生产 Flask 系统或物理设备。多实例应用必须共享这个接收端，不能各自使用内存 Mock。

## RAG、数据与评测

SQL 负责完整的时间/区域/严重度过滤与计数；RAG 返回 documentId、chunkId、score 和内容证据。默认哈希 Embedding 与内存向量库用于可复现工程回归，Milvus REST 适配通过独立容器测试；不代表真实语义质量或完整生产集群验收。

可选 `openai-compatible` Embedding 已接入；本地 BGE-small-zh-v1.5 使用 INT8 ONNX CPU 推理、CLS 池化与 L2 归一化。文档批量编码、查询独立前缀、返回索引与维度验证；超时或错误禁止静默降级为哈希。所有文档编码成功后才替换索引。模型和向量库独立配置，更换维度必须重建对应集合。实现与真实语义对照见 [语义检索评测](SEMANTIC_RETRIEVAL.md)。

确定性快照、DeepSeek 实测、HTTP 模型桩测试分开保存。真实评测固定使用隔离 H2、合成数据和 Mock 工业网关，禁止让自动审批评测控制真实设备。原有关键词基线不执行工具，不能用于端到端模型优劣结论。

Planning v2 的 24 条新题采用冻结源摘要与单次运行标记，首轮结果为 21/24；与旧固定 29/30 分开报告。见 [留出协议](HOLDOUT_PROTOCOL.md)、[首轮结果](HOLDOUT_EVAL.md) 和 [当前评测总览](EVAL_REPORT.md)。普通 CI 仅执行离线测试；外部集成通过手动或 nightly 工作流独立运行。

## 部署与未完成项

首次迁移使用独立空 schema；不能对未知生产库自动 baseline。文件 H2 只用于单应用演示，横向扩容使用 PostgreSQL。首节点完成演示数据初始化后再启动其他节点，正式数据源关闭 demo-data-enabled；初始化不覆盖已有非空事件表。

尚未实现/验收：企业 SSO/MFA、密码轮换与恢复、区域 ABAC、多人会签、数据库备份与故障切换、设备级 fencing、真实工业硬件、审计防篡改、数据清理、跨进程模型累计费用、Milvus 原子版本切换。HTTP 请求已发出但状态未知时需要人工处置，不允许宣传为自动恢复所有工业故障。
